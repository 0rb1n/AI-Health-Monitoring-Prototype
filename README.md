# AI-Based Wearable Health Monitoring Prototype

A comprehensive prototype for real-time health monitoring using simulated wearable sensor data and machine learning algorithms.

## Features

- **Real-time Sensor Data Simulation**: Simulates heart rate, SpO2, body temperature, and activity levels
- **AI-Powered Anomaly Detection**: Machine learning models to detect health anomalies
- **Health Risk Assessment**: Risk scoring based on multiple vital signs
- **Interactive Dashboard**: Web-based visualization for monitoring health metrics
- **Alert System**: Automatic alerts for critical health conditions

## Health Metrics Monitored

1. **Heart Rate**: 60-100 bpm (normal range)
2. **SpO2 (Blood Oxygen)**: 95-100% (normal range)
3. **Body Temperature**: 36.1-37.2°C (normal range)
4. **Activity Level**: Steps, movement intensity
5. **Sleep Quality**: Duration and patterns

## ML Models

- **Anomaly Detection**: Isolation Forest for detecting unusual patterns
- **Risk Prediction**: Random Forest classifier for health risk assessment
- **Time Series Analysis**: LSTM for trend prediction

## Confusion Matrix Explanation

- A confusion matrix (true/false positives/negatives) is not currently generated or documented anywhere in the repository. There is no code that computes or saves a confusion matrix for the risk classifier or anomaly detector.

## Training Dataset Overview

- **Dataset source**: The project uses simulated sensor data generated by `src/sensors/simulator.py`. Example generation and saving to `data/sensor_data.csv` is performed in `src/models/health_monitor.py` (example `__main__` block) and in the simulator examples.

- **Sample size**: The repository contains examples showing how many samples are produced by the simulator depending on parameters. Notably:
  - `GITHUB_SETUP.md` documents "288 test samples generated and validated".
  - The example in `src/models/health_monitor.py` generates 24 hours of data with a 5-minute interval (`duration_minutes=1440`, `interval_seconds=300`) which results in 288 readings.
  - There is no single authoritative dataset file checked into the repo; generated dataset sizes depend on the simulator parameters at runtime.

- **Conditions covered**: The synthetic dataset generation includes:
  - Heart rate, SpO2, body temperature, systolic and diastolic blood pressure, and activity level.
  - Age-based baseline adjustments (`HealthSensorSimulator._get_age_adjustment`).
  - Activity-based variations and circadian effects in heart rate and temperature.
  - Random anomaly injection (default ~5% chance) and optional forced anomaly injection (`inject_anomaly=True`).

## Validation Methodology

- **Data validation**: Implemented in `src/processing/data_processor.py::HealthDataProcessor.validate_reading()` which:
  - Checks required fields (`heart_rate`, `spo2`, `temperature`, `systolic_bp`, `diastolic_bp`).
  - Enforces numeric ranges for vitals (e.g., `heart_rate` 20–300 bpm, `spo2` 0–100%).
  - Validates the relationship that systolic BP must be greater than diastolic BP.

- **Model validation/evaluation**: Implemented in `src/models/health_monitor.py::train_risk_classifier()` which:
  - Creates risk labels using rule-based logic (`create_risk_labels`).
  - Splits data with `train_test_split(..., test_size=0.2)`, using `stratify=y` when class counts permit.
  - Trains a `RandomForestClassifier` and prints training and testing accuracy (via `classifier.score`).
  - There is no implemented cross-validation, no held-out validation beyond the 20% split, and no computation of precision, recall, F1, ROC/AUC, or confusion matrices in code.

- **Tests**: Unit tests (`tests/test_health_monitor.py`) exercise simulator, data processing, anomaly detection training, and risk classifier training, but they do not assert specific numeric evaluation metrics (precision/recall/F1) or perform statistical validation beyond ensuring models can be trained and produce predictions.

## Known Limitations

- Documented numeric metrics beyond accuracy are missing: precision, recall, F1 score, ROC/AUC, and confusion matrices are not computed or saved anywhere in the repo.
- The dataset is synthetic (simulator-based); real-world performance and generalization are therefore not demonstrated in the repository.
- Model evaluation is limited to a single train/test split; no cross-validation or repeated experiments are present.
- The README references `src/models/train_model.py` as a training entrypoint, but that file does not exist in the repository; training is implemented in `src/models/health_monitor.py` via `train_models_from_data()`.
- No explicit documented dataset provenance, labeling process for real-world data, or external dataset references are present.
